## 实现与证据

- `operations/clock.py`：使用带时区的上海时间；拒绝歧义的无时区测试输入。
- `operations/calendar.py`：导入自然日 CSV；严格验证字段、布尔值、重复及覆盖缺口；须调用者确认已核验并提供来源 / 版本。来源、哈希、导入时间存入 `calendar_import`，当前逐日标记存入 `exchange_calendar`。覆盖修订事务化，旧导入审计保留。
- 默认日任务按上海采集时间选择最近已到截止点的交易日；跨时区、周末、模拟休市及覆盖外不会回退到工作日推算。明确日期的未核验手动任务保留警告、标记部分并阻断 AI；未来日、未到截止点的当日阻止执行；已核验休市日跳过，不创建运行或抓取。
- `backfill` 和看板区间补数先检查全部日期范围；默认跳过 AI。只有 CLI 明确 `--with-ai` 才在已核验范围内启用。`catch-up` / 看板最近补跑默认仅一日；多日须明确触发。
- 看板显示应更新日、最近完整日、缺失日期、日历来源与覆盖；未知日历时禁用补跑。空库仍可查看状态，打开或刷新不运行采集，按钮动作及错误保留可查。
- `operations/health.py` 按当前目标日检查状态，历史回填失败单独保留，不覆盖当前健康结果。连续计数必须从应更新日向前连续成功并有当次已核验日历记录，不能累计零散日期。
- Windows 安装脚本只允许中国标准时区、严格验证 HH:mm，并使用 scheduled 触发标记；本轮不注册或更新系统任务。

## 使用与边界

安装依赖后先用 `quantview import-calendar FILE --source SOURCE --version VERSION --verified` 导入已核验日历，再执行 `quantview status`、`quantview run-daily` 或 `quantview catch-up`。文件格式和各命令语义见 README。

- 项目没有内置或导入真实 DCE 日历；测试日历是虚构样本，不可作为运行日历。需要使用者核验实际来源后导入，并维护覆盖范围。
- 本轮用离线行情 / 假模型及假页面动作验收，没有请求真实行情、调用真实 AI、发送邮件或创建系统定时任务。
- Windows 调度和真实年度日历尚未实机 / 真实数据验收。旧审计时间、单写锁、schema 版本、备份迁移属于 P0-02，尚待实现。
- 连续计数排除 `backfill` 和事后生成，不能靠一次历史批量补数通过日常试运行；人工 / 补跑与真正自动调度的验收仍须独立核对。
- 窗口 / 挂牌集合核验、不可变快照、显式 AI 版本和新版三卡看板仍按后续任务推进。
