# 2026-11-02 贵金属国内观察交付

本轮将专项设计中的国内公开观察子集落地：用户可在原 Streamlit 看板侧栏选择“贵金属”。G0／G1 部分完成，G2–G5、ETF 正式账本和公共 E0 基础尚未完成。

## 可使用的功能

| 入口 | 行为 |
|---|---|
| 市场观察 | Au99.99 元／克、Ag99.99 元／千克，日期、来源、5／20 个观测变化、60 个观测窗口回撤、同日参考金银比、单标的趋势与 CSV |
| 基金自选 | 输入实际六位代码、ETF／LOF 和关注金属；本地保存，最多 10 只；明确更新时核验供应商目录类别并采集场内价格 |
| 积存金与实物 | 列明产品、余额单位、成色、赎回／回购价、费用及兑换去重的资料要求；个人登记与估值尚未开放 |
| `quantview metals sync` | 显式采集基准和已保存基金，不依赖 DCE 日历，不启动原期货、AI、邮件或调度 |
| `quantview metals status` | 读取本地行情日期、获取时刻与最近成功／失败状态 |

打开、切页、刷新只读取本地缓存；无缓存展示空状态，失败保留旧成功数据并显示失败原因。成功版本保存标准报价和回溯窗口内原字段、单位／来源／时间、目录核验信息与内容哈希，先写文件再原子发布索引，读取核验哈希。`data/market/metals/` 已加入 Git 忽略，基金清单不代表个人持仓。

首版没有净值／IOPV、折溢价、个人数量与成本、全资产占比或历史个人收益。关注金属为用户标记；目录只能证明行情供应商分类，不能证明基金合同跟踪现货。未请求复权的供应商日线只用于价格观察，不用于含分红总回报。

## 时间和质量边界

- 日期精度来源保存 `observed_at=null`，抓取成功时间作为保守的 `available_at`，不伪装实时或事前已知。
- 上海时间 18:10 前暂缓展示当日数据；这是本地保守就绪规则，不是经核验交易日历。
- SSE／SZSE／SGE 正式日历尚未接入，不声明最近交易日完整。超过 7 个自然日提示陈旧，可在 `config/metals.yaml` 调整；长假须人工核对。
- 未来日期、冲突重复收盘价、无有效价格整批拒绝；非正／非数值收盘价剔除并列出日期和数量。观测变化可能跨缺失日期，不标成连续交易日收益。
- 金银比只用最新同日的同市场指定现货，先把黄金元／克乘 1000，再除白银元／千克；日期、单位或身份不兼容不给比值。它不是可交易套利价。
- 每标的更新最长等待 40 秒；未能核验 ETF／LOF 类别时不继续假装支持。独立文件锁保护此缓存和自选；该锁不替代未来 E0 的数据库统一写入和迁移。

## 本地打开

已安装项目时运行 `quantview ui`；若 macOS 当前没有 `quantview` 命令，可在项目目录运行：

```sh
PYTHONPATH=src .venv/bin/python -m quantview.cli ui
```

补充 macOS 固定地址启动入口：双击项目根目录 `启动QuantView.command`，或运行 `bash scripts/start_ui.sh`，访问 `http://127.0.0.1:8517/`。入口自动定位项目和虚拟环境，无需先激活环境或安装 `quantview` 命令；终端需保持运行，`Control+C` 停止。两个入口已检查脚本语法，实际启动确认 8517 监听成功；不注册开机任务。

选择“贵金属”。新增实际基金后先保存自选，再点击“更新公开行情”。现有 `run-daily`／Windows 定时任务不会自动更新贵金属，没有新增任何系统任务或发送流程。

后续优先补个人资产登记所需的统一写入、迁移与私有快照，再提供积存金／实物 T0 清单和双口径估值；具体产品、银行规则与有效回购报价按实际渠道验收。来源未知或资料缺失不阻止市场观察，也不默认为零成本／零费用。
