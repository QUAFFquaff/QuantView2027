## 1. 产品定位与已确认范围

把 QuantView2027 扩展为“期货研究＋ETF 持仓与复盘”的本地工作台。复用行情适配、质量提示、快照、规则与复盘框架；ETF 使用独立的证券数据和个人账本，不能直接套用期货合约、结算价、主力换月和乘数。

首版流程：选择记账起点 → 确认当日持仓及归属现金 → 导入之后的成交和资金流水 → 对账 → 查看估值和收益 → 记录判断 → 到期复盘。起点前的数据不全也能开始使用。

| 项目 | 首版决定 |
|---|---|
| 资产范围 | 沪深上市、人民币交易的场内 ETF；首批只接用户持有和自选的证券 |
| 类型兼容 | 股票、债券、跨境、黄金／商品等以证券元数据分类；逐类完成数据与公司行动验收后标记支持 |
| 特殊产品 | 货币 ETF 的收益结转等机制未验证前仅观察；遇到未支持的记账事件暂停受影响期间收益发布 |
| 交易方式 | 记录在券商完成的二级市场现货买卖；采用导出文件或手工输入 |

| 时间粒度 | 日终估值、逐笔成交记录；页面总显示数据日期和账本覆盖期 |

## 4. 持仓起点和组合边界

### 4.1 T0 日终起点

用户填写一个明确的日终时点，上传／录入该时点的持仓、现金及未结事项。记录 `as_of`、`recorded_at`、来源文件哈希和确认时间。

- 证券：交易所＋六位字符串代码、份额、成本金额（可缺）、成本定义（券商参考／已核实账面成本）、币种。
- 现金：仅属于本 ETF 组合的现金，不自动把券商全账户余额划给 ETF。
- 未结事项：待收分红、已成交待结算款、转入转出中的份额等；未解释的差异阻止完整估值。
- T0 未复权市场价格和估值来源必须可追溯。起点市值用于后续表现，不替代历史买入成本。
- 历史成本未知时，可显示市值；“相对原买入成本的浮盈／已实现损益”显示未知。若 T0 估值及后续记录齐备，仍可计算 T0 以来的损益。
- 只有 T0 之后事件纳入日常重放。T0 当日流水须按起点覆盖标记排除，不能再次累计。
- 后续补齐 T0 之前历史，走“新基线＋历史重建”预览并确认，发布新版本；旧快照和旧复盘不被替换。

例：T0 持有 1,000 份、价格 2 元、原成本 1,700 元、现金 1,000 元，起点资产为 3,000 元。此后价格变为 2.10 元且没有交易，起点以来损益是 100 元；相对原成本浮盈是 400 元。两者同时展示时必须注明口径。

### 4.2 ETF 子组合与完整券商账户

默认 `scope=etf_sleeve`：只计 ETF 与明确划入的现金。买卖其他股票等事件保留为未纳入条目，提示需要补充子组合资金划拨，不静默忽略后仍声称券商全账户已对账。

可选 `scope=broker_account` 仅在该账户所有资产和资金活动均受支持、均纳入时启用。账户混有股票、逆回购、理财或融资等未支持资产时，不开放“完整账户收益”。

现金未明确分配时降级为“ETF 持仓市值视图”：不计算含现金仓位、组合收益率和组合回撤。多个账户内部转账在单账户视角是外部流；未来合并视角需用 transfer_group 配对抵销，不能把两次资金划拨算成收益。

## 5. 导入、记账与对账

### 5.1 输入契约（模板待实现）

| 输入 | 必要字段 | 可缺但需降级的字段 |
|---|---|---|
| 起点持仓 | account_alias、as_of、exchange、code、quantity、currency | cost_amount、cost_basis_type、来源证据 |
| 成交明细 | account_alias、trade_date、exchange、code、BUY/SELL、quantity、gross_amount、currency、可确定的成交顺序 | execution_id、trade_time、price、fees；缺费用时净收益待核对 |
| 资金流水 | account_alias、booking_date、event_type、signed_cash_amount、currency、流水标识或导入行引用 | settlement_date、关联成交／分红 ID、备注 |
| 对账快照 | account_alias、as_of、证券份额、现金余额及余额定义 | 券商成本与参考盈亏，仅用于差异解释 |

费用拆为佣金、其他费用、已知税费，并保存原文；未给出费用和明确零费用是两种状态。金额和份额使用 Decimal／数据库 DECIMAL，不用浮点数累计账本。价格、数量单位以证券／供应商元数据校验，ETF 持仓单位统一为“份”。

### 5.2 导入流水线

1. 原文件保存在本地私有目录，记录 hash、导入时间、模板版本和账户别名。
2. 映射字段，规范代码／交易所、日期、单位、资金正负号；保存原值和行定位。
3. 预览新增、重复、冲突、未支持、格式错误及对现金／持仓的影响；错误行定位到字段。
4. 重复识别优先账户＋业务日期＋成交／流水 ID，并保留版本。无可靠 ID 时用规范化业务指纹作为候选重复，不自动丢弃可能是真实的两笔同价同量成交。
5. 同文件重复导入幂等；跨文件重叠需识别。不能只用文件名或文件 hash 处理所有重复情况。
6. 用户确认后，在全局写锁内再次检查账本版本与重复项，事务性写入事件和会计分录。默认整批有错误不入账；显式剔除行后须重新预览，不悄悄部分成功。
7. 成交产生一次现金分录。资金流水中对应的成交扣款／到账用于匹配对账，不再次入账；独立费用关联原成交，避免两份导出重复扣费。
8. 重放后与券商日终持仓及现金对账，发布对账结果和账本版本；错误未消除时保留输入并阻止正式绩效发布。

输入文件允许 CSV 与无宏 XLSX；限制大小、表格行数和目录，不执行公式或外链。导出 CSV 时防止用户文本被表格软件作为公式执行。券商专用映射在拿到脱敏列名和样例后新增，不提前声称通用兼容。

### 5.3 事件和会计规则

`BUY / SELL / FEE / DEPOSIT / WITHDRAWAL / DIVIDEND_ENTITLEMENT / DIVIDEND_RECEIPT / SPLIT / TRANSFER_IN / TRANSFER_OUT / REVERSAL`，每种事件都有可用状态和来源。

- 买入增加份额、减少资金；卖出减少份额、增加净资金。买卖本身属于组合内部资产转换。
- 入金／出金是外部流，不是损益；ETF 组合内收到的分红属于投资收益，转出组合才另记外部流。
- 交易按成交时点确认持仓；已成交未结算款使用应收／应付过渡科目，结算时清零。若券商资金余额已包含成交影响，映射须明确并抵销过渡项，不能重复计入。
- 回转交易资格、交收周期、可卖数量和可取现金分别建模，不能用一个“T+0”字段概括；本系统不据此发出订单。
- 同日成交用时间＋券商序号排序；缺少能决定成本归属的先后关系时要求补充，不按文件偶然顺序猜测。
- 卖出数量超过已核实可解释持仓、未知负现金、转入缺数量／成本等形成冲突；不自动补假买入或假入金。
- 变更采用冲销＋替代事件，记录理由、引用及提交 ID。更正后重算新版本，不物理覆盖旧事件。
- 转入携带可追溯的成本和边界估值；跨组合划拨按该组合边界记录外部流。来源成本未知仍保留未知。

### 5.4 分红与拆并份额

分红根据确认的权益登记日持仓确定资格；除息日建立应收分红，到账日将应收转现金，不能在两个日期各算一次收益。历史基线之前形成但之后到账的权益须在起点单列。事件日期、每份金额、税费或资格无法确认时，相关收益状态为待核对。

拆分／合并改变份额及单位成本，不应改变总成本；零碎份额现金补偿单列事件。未知公司行动不能用“价格突然涨跌”替代解释。普通现金分红首版可人工核验录入，不能等待自动抓取才记账。

## 6. 估值与收益：先算清金额，再开放比率

### 6.1 估值与成本

估值使用未复权市场价格：`V = Σ(份额 × 价格) + 现金 + 已确认应收 − 已确认应付`。净值和 IOPV 不替代场内持仓的市场价格。

首版采用按账户、证券逐笔移动加权平均的管理账成本：买入成本增加成交额＋明确买入费用；卖出按卖出前平均成本释放。卖出已实现损益＝卖出净额−释放成本；浮动损益＝剩余市值−剩余成本。该口径为系统管理账，不强称与券商摊薄成本或税务口径一致。

行情缺失时可单列“按最后可用价格的参考估值”，必须显示报价日期、停牌／缺失原因、受影响市值；不能填零或标成完整估值。无可靠价格的证券使总资产不完整，正式收益率暂停；其余持仓仍可查看。

### 6.2 起点以来与期间损益

给定完整区间：`期间损益 = V_end − V_start − 净外部流入`。转入证券等非现金外部流按边界时点的可核验价值计入。费用已反映在现金中，不能再次从这一资产差公式扣除。

成交成本口径的已实现／浮动损益，与基线起点以来的表现分别保存；起点前浮盈不算进起点后收益。分红、费用、价格变化及差异项可作为损益解释，未解释差异不能归给“其他收益”。

### 6.3 收益率、回撤及比较

| 指标 | 开放条件和定义 |
|---|---|
| 持仓价格变化 | 真实同一证券、相同价格口径；独立于个人投资收益 |
| 无外部流期间收益 | 完整估值、现金与费用对账后，用期间损益／期初资产；分母非正时不输出 |
| 有外部流期间收益 | 先以 Modified Dietz 估算，明确“现金流调整估算收益”；不称精确 TWR |
| 精确 TWR | 后续只有取得每次外部流边界的完整估值时才开放；子期间几何链接 |
| 个人资金加权回报 | XIRR 后续可选；披露起点与日期，对无解、多解、短区间年化设明确状态 |
| 回撤 | 由已发布的现金流调整收益序列计算；若用估算序列，标“估算回撤”；不对原始资产金额曲线直接算回撤 |
| 基准比较 | 用户指定、版本化；相同日期、币种与价格／总回报定义，缺样本不补造；ETF 收盘价与基金 NAV 绩效分开比较 |

Modified Dietz 设计：`R = (V_end − V_start − ΣCF_i) / (V_start + Σw_i CF_i)`，外部流入为正。只有日级流水时固定按日末发生、`w_i=(D−d_i)/D`；保存方法版本。无法确定所属日期、区间为零、分母非正、出现资产耗尽后重新注资时，不跨越该边界拼接；需划分新片段。大额流或波动区间突出估算限制。该方法参考 [GIPS 计算说明](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/)，本项目不声明 GIPS 合规。

首版完整账本可交付金额损益；现金流收益率与回撤作为单独验收项逐步开放。夏普、胜率、精细归因和“择时能力”不在首版首页。

### 6.4 必须通过的算例

初始现金 5,000 元，零持仓；买 1,000 份×2 元、费用 5 元；再买 500 份×2.2 元、费用 5 元；卖 600 份×2.3 元、费用 5 元；收盘 2.25 元，无其他事件：

- 总买入成本 3,110 元；卖出释放成本 1,244 元；卖出净额 1,375 元，已实现损益 131 元。
- 剩余 900 份、成本 1,866 元、市值 2,025 元，浮动损益 159 元。
- 现金 3,265 元，资产 5,290 元，损益 290 元＝131＋159。
- 若再入金 1,000 元，资产 6,290 元，但损益仍为 290 元。

| 数据 | 权威／候选来源 | 入库规则 |
|---|---|---|
| 证券身份、上市／终止、跟踪标的、产品类型 | 交易所、基金管理人披露；供应商目录辅助 | 代码保存字符串；交易所必填；保存有效期与核验依据 |
| OHLC、量额 | `fund_etf_hist_em(adjust="")`；备选 `fund_etf_hist_sina` | 保存原响应、供应商版本、抓取时间、量额原单位；未核实不自动乘 100 |
| NAV、分红、拆并份额 | 基金管理人公告／正式披露优先；供应商数据交叉核对 | 分开保存净值所属日、发布日期、抓取时间和修订版本 |
| IOPV | 仅有可靠来源、时点和方法说明时接入 | 可缺；不可作为正式净值或个人资产估值的替代 |
| 交易日历／业务规则 | SSE / SZSE 官方日历、规则和产品公告 | 日期与生效版本可查；未知不回退为简单工作日；旧 DCE 日历不复用为证券日历 |
| 持仓、成交、现金、实际费用 | 用户券商导出及确认记录 | 用户私有事实，与市场数据分开治理 |

AKShare 文档明确区分不复权、前复权、后复权历史行情。个人账本使用真实成交及未复权价格，加上明确分红／份额事件；调整序列仅用于研究展示，不与分红现金流重复计算收益。[接口文档](https://akshare.akfamily.xyz/data/fund/fund_public.html)

价格与 NAV 对齐日期、币种及可用时间后才能标“对应日折溢价”。若只有更早净值，只展示“相对历史净值的参考偏离”，显示两个日期；跨境 ETF 还要显示标的市场时间差和汇率口径。IOPV 与正式净值可能不同，产品披露对此有明确风险说明。[交易所披露的基金文件示例](https://www.sse.com.cn/disclosure/fund/announcement/c/new/2026-04-30/513850_20260430_LQAJ.pdf)

不为所有 ETF 写死相同的回转交易、涨跌幅、最小交易单位、费用和结算规则。元数据按证券及有效期管理，缺依据显示未知；历史成交照实记录，规则核查另列结果。[上交所现行规则及生效／暂缓实施说明](https://www.sse.com.cn/lawandrules/sselawsrules2025/fund/trading/c/c_20260424_10817739.shtml)

## 8. 判断记录、纪律与复盘闭环

### 8.1 事前／当时记录

字段：账户／组合、ETF 或组合主题、动作类型（观察／未操作／计划买入／增持／减持／退出）、理由、证据、推翻条件、预期持有期限、复盘日、可选的数量／金额／权重计划、适用纪律版本。

数量／权重为用户填写的记录，不生成交易指令。建议条件包括持仓集中度、允许的产品范围、再平衡条件、参考溢价条件、信息核验要求；阈值留空，用户自行配置并激活。缺价格、净值、现金、账本或窗口时，依赖这些字段的规则结果为 unknown。

保存 `decision_at`、实际 `recorded_at`、`available_at` 和引用版本。原判断正文冻结；后补明确标识。今日补建的昨日快照不能被判为昨日决策已经看过的证据，复盘可以另列事后重建结果。

### 8.2 交易事实与判断的关联

一条判断可关联多笔成交；同一成交可按数量分配给多个研究主题，但分配量总和不得超过成交量。首版提供用户确认关联，不按日期或涨跌自动判定属于某次策略。

复盘页同时显示：

1. 当时理由、反证、纪律版本、原市场与持仓快照。
2. 实际成交数量／价格／费用，计划与实际的差异；无成交时保留未操作状态。
3. 后续价格、证据和实际账本损益；无法分配损益的主题仅显示观察区间价格变化。
4. 证据评价 `supported / invalidated / mixed / insufficient_data`。
5. 执行评价 `compliant / violated / unknown / not_applicable`、原因与下一次复盘日。

赚钱与遵守纪律分开评价；AI 可整理用户文字和已授权证据，不自行认定纪律合规，也不为导入的成交补造事前理由。

### 8.3 周度复盘

首版按上海时区自然周统计：待复盘／已完成／逾期数量、计划与实际差异、费用、用户问题标签、未知条件；只有相应期间账本与行情完整才显示期间损益和收益率。无适用样本时显示无样本。主题标签和资产类别可做分组，真实行业穿透需带日期的成分持仓数据，不能仅凭 ETF 名称推算。

## 9. 数据模型、版本及模块划分

### 9.1 表和身份（计划新增）

| 表／实体 | 关键字段与约束 |
|---|---|
| `security_master` / `security_version` | security_id、exchange＋code、asset_class=etf、type、currency、标的、有效区间、来源；不更改现有期货 instrument 语义 |
| `etf_quote_version` / 当前行情视图 | security_id、trade_date、source、price_basis、revision、OHLC、量额及原单位、observed_at、available_at、quality、raw_batch_id |
| `fund_nav_version` / `corporate_action_version` | 所属日、披露／可用时间、币种、行动类型及日期、版本、来源；价格与 NAV 独立更新 |
| `portfolio` / `account_alias` / `opening_balance_version` | 组合范围、币种、账户映射、T0、份额、归属现金、成本语义、应收应付、确认状态 |
| `import_batch` / `import_row` | 文件哈希、映射版本、原行、候选重复键、解析／确认状态；批次保存账本基准版本 |
| `ledger_event` / `ledger_posting` | event_id、业务与入账时间、账户、证券、数量、金额、费用状态、来源、反向事件、提交 ID；原事件不可变 |
| `reconciliation` | 账本版本、对账日期、券商快照引用、数量／现金差异、成本口径差异、状态与解释 |
| `position_daily` / `portfolio_daily` | 可重建计算视图；存 ledger_version、price_version、method_version、完整性及阻断原因 |
| `portfolio_snapshot` | 不可变私有估值与持仓版本，引用账本、行情快照、对账记录及计算方法 |
| `decision_version` / `review_version` / `decision_execution_link` | 扩展通用日志，subject 支持 ETF／期货／组合；关联计划与事实，不覆盖原文 |

金额建议 `DECIMAL(24,8)`，份额 `DECIMAL(24,8)`，计算保留更高精度，展示层按币种舍入；原始数值和舍入规则保留。完整性至少分开保存 `market_status / ledger_status / valuation_status / cost_status / performance_status`，一个绿色“成功”不能掩盖未知成本。

### 9.2 快照与恢复

公共 `ResearchSnapshot` 保存市场证据；私有 `PortfolioSnapshot` 保存资产和账本引用。复盘可同时引用二者，并记录真正可用时间。已发布快照写临时文件、校验、原子改名后登记索引，复用原工作台发布／孤立文件恢复设计。

同一输入复用结果；行情修正、账本更正或方法变更发布新版本。每日视图可重建，但原快照、原判断、原复盘不重写。跨期修正使受影响后续期间标记待重算，对账重新验证后才能发布新结果。

### 9.3 代码边界

```text
market/etf/          ETF 目录、行情、净值、公司行动适配与质量
portfolio/imports/  券商文件映射、预览、去重和冲突
portfolio/ledger.py 事件、分录、余额与成本重放
portfolio/valuation.py / performance.py 估值、损益、收益口径
portfolio/reconcile.py / snapshots.py   对账和私有快照
discipline/ + journal/ + reviews/        复用通用纪律和复盘服务
ui/etf/             只调用查询／提交服务的页面
```

沿用一个本地 DuckDB 和统一写入服务；暂不新增后台微服务。扩展 calendar 配置为按市场登记，保留旧 `calendar.exchange=DCE` 的兼容迁移；期货 `run-daily` 的已有含义不静默变成 ETF 同步。

写锁不能替代 DuckDB 的跨进程访问限制。读连接保持短生命周期；UI 与采集／导入争用时有界重试并提示稍后刷新，不因连接失败创建新库或跳过记账。所有写入口均经统一服务串行执行，备份时拒绝新写入。

建议后续命令分组为 `etf sync`、`portfolio import --preview`、`portfolio reconcile`、`portfolio rebuild --preview`；均为接口草案，当前不可执行。导入确认和历史重建须有显式提交动作，网页刷新没有写入副作用。

## 10. 本地隐私与备份

个人原文件、导入暂存、账本导出、私有快照与备份放在 `data/personal/`、`reports/personal/` 和受控备份目录，功能开发时先补 Git 忽略与脱敏日志。数据库含个人数据后整库按私有数据管理，不能当公共研究数据上传。

账户只保存本地别名，首版不要求登录密码或券商凭据。市场 AI 默认只接公开行情证据；持仓金额、成交明细和原交割单不进入外部模型。将来允许个人复盘 AI 时，需提供数据范围预览并由用户启用。

备份需获取全局写锁、关闭写连接、复制数据库与相关档案清单并校验；恢复先在隔离目录验证外键／哈希／余额，再切换。常规删除采用作废事件；彻底清除个人数据与其备份走独立显式流程。

## 11. 分阶段实施与退出条件

|---|---|---|

| E2 账本 MVP | T0 持仓／现金、通用导入＋一个实际券商映射、费用／分红／拆分、去重、对账、持仓页、私有快照 | 起点后完整回放与券商一致；金额损益通过算例；重复导入不重复扣款 |

| E4 绩效增强 | 现金流调整收益、回撤、可选基准；ETF 类型逐类扩展 | 入金不形成利润／回撤；未知／大额流估算状态正确；每个支持类型通过公司行动测试 |
| E5 日常自动化 | 多市场日终调度、失败恢复、统一摘要、邮件预览及可选通知 | 连续 5 个已核验交易日可解释运行，关闭电脑后显式补跑，邮件不重复 |

首个可用版本目标是 E0–E3：能看清持仓、对上账、保存判断并复盘。E4 不阻塞先使用完整的金额账本；E5 中邮件投递沿用原 P3，不另造第二套。只读 E1 可先做，但不能绕过 E0 就接入真实账本写入。暂不承诺固定工期，券商样例、持仓类型和历史质量决定导入工作量。

## 12. 验收场景

| ID | 场景 | 预期 |
|---|---|---|
| ETF-AT01 | 仅期初持仓、未知成本／现金 | 展示可知市值；成本盈亏与组合收益不填零 |
| ETF-AT02 | 两次买入、部分卖出、费用 | 第 6.4 节份额、现金、成本、损益完全一致 |
| ETF-AT03 | 同文件重复／跨文件重叠／两笔同价同量真实成交 | 前两者提示并去重，后一种不误删；确认入账事务幂等 |
| ETF-AT04 | 成交单和资金单同时含扣款及佣金 | 每个经济事件只入账一次；未匹配项可见 |
| ETF-AT05 | 入金、出金、子组合划拨、完整账户混入非 ETF | 净流入不变成收益；不把不完整子组合称为完整账户 |
| ETF-AT06 | 部分卖出、跨日结算、缺同日成交顺序 | 正确过渡科目；无法确定顺序时阻断相关成本发布 |
| ETF-AT07 | 除息到到账有间隔、拆并份额 | 应收转现金不重复收益；拆分不制造损益；未知事件降级 |
| ETF-AT08 | 停牌、缺价、过期 NAV、跨境时差 | 日期与估值状态显著展示；无假日涨跌、无伪同步折溢价 |
| ETF-AT09 | 账本更正、历史重建、价格修订 | 新版本可核验，原判断／快照／复盘引用不变 |
| ETF-AT10 | 晚补判断、引用决策之后才发布的数据 | 明确后补，不判为事前纪律通过 |
| ETF-AT11 | 并发导入／补数、保存失败、发布中断 | 全局单写；不丢表单；半成品不可见且可恢复 |
| ETF-AT12 | 外部流估算、非正分母、资产清零再注资 | 指标正确命名，失效片段不拼接；无伪回撤 |
| ETF-AT13 | 备份恢复、导出、截图和 AI 调用 | 私有档案引用一致，公共输出无个人成交与账户资料 |
