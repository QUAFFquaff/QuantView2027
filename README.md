# QuantView2027

QuantView2027 是一个本地个人投研工作台。目前提供 DCE 农产品期货研究，以及上金所金银现货、ETF／LOF 自选的贵金属观察页。农产品模块覆盖 LH（生猪）、JD（鸡蛋）和 C（玉米）的日行情、跨期价差、成交与持仓变化、AI 多空分析及 Markdown 日报。

系统仅用于研究，不包含实盘、模拟盘、账户连接或订单执行功能。

## 快速开始

要求 Python 3.11 或更高版本。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
quantview init-db
quantview doctor
# 同步公开年度日历并保存备份；已有备份时直接从本地恢复
quantview sync-calendar --year 2026
quantview status
quantview run-daily
quantview ui
```

未配置 AI Key 时，行情、指标和 Markdown 日报仍会正常生成，只跳过 AI 章节。

每日任务会核对目标日的已知合约覆盖：主源缺少有效当日行情时尝试备源；已知合约缺失或有效合约不足时标记 `partial`，跳过对应品种 AI，并在日报和工作台列出缺口与质量警告。最低合约数由 `config/app.yaml` 的 `data_quality.min_contracts_per_product` 配置，默认 2。完整性仅相对于本次发现或本地候选合约集合，不代表已核验交易所全量挂牌合约。

## 日常使用

macOS：在项目文件夹双击 `启动QuantView.command`，或在终端运行：

```sh
bash /Users/quaff/Documents/program/Quantview2027/scripts/start_ui.sh
```

启动后访问 <http://127.0.0.1:8517/>。保持该终端窗口运行；按 `Control+C` 停止服务。页面出现 `Connection error` 时，先确认启动窗口仍在运行，再重新执行上述入口并刷新页面。只打开网址不会启动服务；此入口不创建开机任务，也不采集行情。

Windows：

```powershell
.\scripts\start_ui.ps1
```

工作台侧栏显示应更新交易日、最近完整日、日历来源与覆盖、历史品种摘要缺口。“历史补数与运行核验”将缺少品种摘要的日期与已有摘要、缺少完整日终任务记录的日期分开显示，可按明确显示的日期重跑；历史区间补数默认关闭 AI。打开或刷新页面不会启动采集或 AI。当前选日所需日历未知时最新日采集禁用，历史计划的日历缺口不阻止已核验最新日采集；已有数据仍可浏览，也可在页面明确指定日期采集。

侧栏“交易日历与本地备份”可按年度同步、查看来源版本并下载 CSV。已有备份时默认不联网，只有勾选“重新联网校验”才重新下载；主区“查看交易日历”提供开市／休市月历，未知年份明确标为未覆盖。通常每年补充一次，交易所临时调整时再手动校验；不创建额外定时任务。

页面顶部按交易日判断当前行情是否更新就绪，提供“采集最新已就绪行情”；已完成时明确显示成功与重新采集日期。最新按钮始终选择当前应更新日，不会退回旧的待核验任务日期。交易日 18:10 前明确提示尚未到当日日终采集时间，显示前一个已就绪交易日属于正常情况。日历未知时，展开“明确指定日期采集”，核对日期并勾选确认后可手动更新；未来日期、已核验休市日及未到 18:10 的当日仍被阻止。新入口关闭 AI；失败保留原行情并显示原因，部分结果不标成完整成功。刷新按钮只重新读取本地数据。

看板提供四个入口：首页三品种卡片与重要变化、真实合约研究、历史期限结构对照与固定合约对价差、日报与系统状态。主力切换分段绘制，AI 默认折叠；支持合约 CSV 与 Markdown 日报下载。失败日期与空库也可浏览系统状态，390px 窄屏按单列显示。

农产品看板使用可修订的数据库最新查询，暂不提供不可变快照与版本切换。规则显示“未配置”，个人记录、复盘和邮件尚未接入；链式指标与价差统计按入库观测计算，交易日连续性仍需核验。详见 [10 月 27 日看板交付](docs/PROGRESS_2026-10-27.md)。

### 贵金属工作台

侧栏选择“贵金属”即可查看。首次使用点击“更新公开行情”；本次已采集 Au99.99（元／克）和 Ag99.99（元／千克）公开日线。页面显示行情日期、来源、5／20 个观测的价格变化、60 个观测的窗口回撤、同日参考金银比、趋势图和 CSV 下载。打开或刷新页面不会联网，也不受 DCE 日历缺失阻塞。

在“基金自选”每行填写 `代码, ETF或LOF, 黄金或白银或未确认` 并保存，再点击更新。保存的是观察清单，最多 10 只；类型需通过行情供应商目录核验，关注金属是用户标记，不能替代基金合同核验。没有预置任何个人持仓；净值、折溢价与个人收益尚未提供。

贵金属为日线参考，当日数据在上海时间 18:10 前不展示；各市场日历尚未接入，不能据此声明交易日完整或实时。超过 7 个自然日的行情提示陈旧，阈值与回溯范围见 `config/metals.yaml`。失败保留旧行情并显示失败原因；成功数据按版本保存至 Git 忽略的 `data/market/metals/`，自选也仅保存在该本地目录，不进入 AI 或邮件。

“积存金与实物”列出了后续需要记录的产品、余额、成色和赎回／回购费用。个人余额、成本、双口径估值与复盘仍待实现。完整交付与验证见 [11 月 2 日记录](docs/PROGRESS_2026-11-02.md)。

安装工作日 18:10 自动任务（Windows 必须使用中国标准时间；采集时间应与 `config/app.yaml` 一致）：

```powershell
.\scripts\install_scheduled_task.ps1
```

安装定时任务会修改 Windows 任务计划，应由用户明确运行；项目不会自行注册系统任务。

## 常用命令

```powershell
quantview doctor
quantview status --date 2026-10-22
quantview init-db
quantview sync-calendar --year 2026
quantview sync-calendar --year 2026 --refresh
quantview sync-calendar --year 2026 --offline
quantview import-calendar data/exports/dce_calendar.csv --source "已核验来源" --version "来源版本" --verified
quantview discover-contracts
quantview run-daily
quantview run-daily --date 2026-10-20
quantview catch-up
quantview catch-up --all
quantview backfill --start 2026-10-01 --end 2026-10-20
quantview import-file data/exports/manual_daily.csv
quantview metals sync
quantview metals status
quantview ui
```

手工文件需包含 `contract_code`（或 `symbol`/`合约`/`合约代码`）以及日期、OHLC、成交量和持仓量字段；字段可使用系统标准英文名或 AKShare 常见中文名。

macOS 在项目目录直接运行贵金属页（已有 `.venv` 且依赖已安装）：

```sh
PYTHONPATH=src .venv/bin/python -m quantview.cli metals sync
PYTHONPATH=src .venv/bin/python -m quantview.cli ui --port 8517
```

`metals sync` 只更新公开金银基准和已保存的基金自选，不运行农产品、AI 或邮件；`metals status` 只读本地数据。现有 `run-daily` 和 Windows 定时任务不会自动采集贵金属。

### 基金价格与暴露

侧栏选择「基金价格与暴露」。「追加七只观察样例」保留已有自选；「更新基金日线」只刷新基金，复用贵金属页的行情缓存。报价日期与证券市值快照日期分别显示，行情不会改写历史快照。

在「行情与自选」中可直接搜索公开观察样例，或手工添加代码、选择 ETF／LOF 和可选关注分类；重复填写同一代码可更新分类，也可移除自选。最多 10 只，自选不代表持仓，保存不自动联网。贵金属与基金页共用清单；并发修改冲突时拒绝覆盖并保留输入。

「持仓快照与穿透」支持直接填表，或导入 CSV／XLSX 后映射代码列和市值列，再填写快照时点、证券总市值（不含现金）及来源。最大 1 MiB、500 行，Excel 读取第一个工作表且不接受公式。先「校验并预览」，再「确认保存」；重复代码、非正市值、基金合计超过总市值及未来时点会被拒绝。修改输入使预览失效；保存失败保留输入，历史版本可查看和导出，相同内容重复保存不增加版本。

已有 JSON 快照仍可导入公开披露；表格更新保留当前已导入的披露。成分权重例如 5% 填 `0.05`。缺报告、未披露部分和范围外市值单列；期货和黄金现货类基金不做股票穿透。此页不计算净值、折溢价或个人收益，也不会自动联网。

快照留在本地 `data/portfolio/`，原始私有资料可放在 `Assets/`；这两个目录及行情、自选缓存均被 Git 忽略。详见 [ETF 设计第 15 节](docs/ETF_PORTFOLIO_DESIGN.md#15-基金价格与暴露首版)。

## 交易日历与日期规则

- 推荐使用 `sync-calendar`：读取 [Markets Open 的年度公开日历](https://marketsopen.today/zh/datasets)，按 DCE 范围核验年份、时区、完整节假日组、复市日期及原始公告链接，再依据周末和休市区间生成逐自然日表。数据采用 CC BY 4.0，保留署名和 data_version；第三方事实整理不冒充交易所直连或实时状态。
- 备份位于 `data/reference/calendars/DCE/<年份>/`：`latest.json` 指向以来源 SHA256 命名的版本目录，保留原始 `source.json`、逐日 `calendar.csv` 和含来源／许可／日期／哈希的 `manifest.json`。相同版本不重复归档或导入，变化版本保留旧副本；首次下载会在本地导入，之后默认直接使用备份，`--refresh` 明确联网、`--offline` 仅从本地恢复数据库。公开参考备份可随代码保存，私有持仓不包含在内。
- 当前已经同步 2026-01-01 至 2026-12-31 的 365 个自然日、242 个 DCE 交易日；2027 等年份只有公开源完整载入 DCE 数据后才可同步，不用普通工作日历推算。该表只供日线选日与补数，不提供夜盘时段或结算安排。同步日历不会采集市场行情，也不会追溯修改旧运行的质量状态。
- `import-calendar` 的 CSV 仅含 `trade_date,is_trading_day` 两列。日期使用 `YYYY-MM-DD`，标记使用 `0/1` 或 `true/false`；须覆盖区间内每个自然日，包含周末和节假日。重复、缺口和非法值拒绝导入；覆盖修订在事务中完成，旧导入的来源、版本、时间与文件哈希保留。
- `import-calendar --verified` 是调用者确认已核验自备文件，应用不会自动认证任意文件为官方日历。测试样本不能用作运行日历；可用自备 CSV 覆盖已核验的临时调整，并按年份维护覆盖。
- 不指定 `run-daily --date` 时，按上海当前时间及 `pipeline.scheduled_time`（默认 18:10）选最近已到采集时间的交易日。休市日或收盘前可选前一交易日，未知日历或覆盖缺口不回退到工作日推算。
- 明确指定的未来日期或尚未到采集时间的当日被阻止；已核验非交易日返回 `skipped`，不采集。过去日期若未被日历覆盖，仅明确日期的手动运行可继续，记录警告、标记 `partial` 并跳过 AI。调度与受控补跑不能绕过日历检查。
- `backfill` 先核验整个区间，再执行其中的交易日；默认不调用 AI，需明确 `--with-ai` 才启用。`catch-up` 默认重建最近一个缺少完整日终记录的日期，`--all` 明确重建所显示日期。空库默认只提示最近应更新的一日。
- `catch-up` 的旧字段 `missing_dates` 指缺少已核验完整日终运行／发布记录，并不代表这些日期一定没有行情。`status.history` 单列品种摘要行缺口与已有摘要的待核验日期，不修改历史审计，也不据此宣称历史全合约完整。更新最新日使用 `run-daily --no-ai` 或页面最新按钮，历史核验使用 `catch-up` 或侧栏明确显示日期的重跑入口。
- `status` 默认按上海当前时刻判断，`status --date` 按指定日的采集截止时间评估。连续计数从应更新日向前，遇到未成功或未知日期即中断；历史回填和事后生成不计入。该计数尚不代替真实行情、快照及自动运行的完整验收。
